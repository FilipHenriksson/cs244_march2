Modern LLM-powered agent systems accomplish complex tasks through multi-step workflows composed of interdependent LLM calls, often across thousands of concurrent tenants competing for the same organizational rate. Recent work in this space [1]  exploits DAG structure to coordinate dependent LLM calls on an inference cluster which the application is assumed to own, an assumption that does not hold when applications depend on external API providers (OpenAI, Anthropic, etc.) with independent and opaque rate limits. In this work, we design a scheduling proxy service implemented at the organization level to intelligently dispatch requests from multiple concurrent sessions to a single LLM provider that optimizes for mean latency and token per minute and request per minute rate limits. We evaluate six scheduling strategies — FIFO, shortest-job-first (SJF), adaptive SJF with learned duration estimates, exponential backoff, a DAG-aware MapReduce policy that prioritizes requests whose fan-out groups are nearest to completion, and a combined policy that multiplies predicted duration by remaining group size. Across 15 trials of a multi-tenant agent workload, the DAG-aware MapReduce scheduler achieves the lowest mean latency (645.64s vs. 725.64s for SJF and 719.52s for FIFO), an 11% improvement over the FIFO baseline, with comparable per-session cost (~$0.087). The combined policy ranks second (661.86s mean), suggesting that exploiting workflow structure to reduce head-of-line blocking at fan-in barriers is the dominant mechanism, while job-size estimation provides a modest additional signal. These preliminary results demonstrate that even a lightweight, DAG-aware proxy sitting between tenants and an opaque rate-limited API can meaningfully reduce end-to-end latency without requiring any cooperation from the inference provider.
